Mit GitLab verbinden

Die Häkchen sind die GitLab-Issues: Abhaken schließt das Issue, und alle sehen, wer was erledigt hat. Dafür verbindet sich jede Person einmal mit dem eigenen GitLab-Zugang.

  1. Personal Access Token in GitLab erstellen – Scope api, Ablaufdatum spätestens 21.12.2026.
  2. Token kopieren und hier einfügen.

Der Token bleibt nur in deinem Browser und wird ausschließlich an gitlab.com geschickt. „Trennen“ löscht ihn wieder.

Neue Aufgabe

„Zum Plan hinzufügen“ speichert die Aufgabe für alle auf der GitLab-Wiki-Seite Sprintplan-Zusatzaufgaben; das GitLab-Issue legst du wie gewohnt mit „Issue erstellen“ an, wenn du anfängst.

    So läuft jedes Issue

    Verbindlich laut den Projektanforderungen. Ein Issue gilt erst als erledigt, wenn es über diesen Weg in dev gelandet ist.

    1. Issue anlegen

      Beschreibung, Acceptance Criteria, Weight, Assignee und Sprint-Milestone. Bugs sind eigene Issues.

    2. Feature-Branch

      Immer vom aktuellen dev: git switch dev, git pull, dann git switch -c feature/12-kurzbeschreibung.

    3. Commits

      Klein und mit Issue-Bezug: git commit -m "Add score calculation (#12)", danach git push.

    4. Merge Request nach dev

      Mit Closes #12, kurzer Beschreibung der Umsetzung und den getesteten Funktionen. Pipeline muss grün sein.

    5. Review

      Eine andere Person prüft Acceptance Criteria und Definition of Done und schreibt einen inhaltlichen Kommentar.

    6. Merge

      Nie durch den Autor. Kein Squash, Feature-Branch nicht löschen, dev niemals löschen.

    7. Release

      Merge Request dev → main, annotierter Tag (v1.0.0) und GitLab Release. main deployt automatisch.

    Zeiterfassung: /spend 45m plus Tätigkeit und Issue, höchstens 50 Minuten pro Eintrag – auch für Reviews und Merge Requests.

    Nicht warten: Während ein Merge Request im Review ist, das nächste Issue auf einem neuen Branch von dev beginnen.

    Abhaken schließt das GitLab-Issue, Entfernen öffnet es wieder. Laut Projektregeln wird ein Issue normalerweise über den Merge Request mit Closes #… geschlossen – dann erscheint es hier automatisch als erledigt.
